Kilrr OS: System Handover & SOPs

Prepared by Muaz Jameer Attar | Factory Manager

Welcome to the System. I built this Kilrr OS software from scratch to digitize our factory floor, completely eliminate manual Excel sheets, and guarantee 100% FSSAI traceability for our blended spices.

If you are reading this, you are now responsible for floor operations. Do not panic if you don't know how to code. This document will tell you exactly how to run the floor, how to survive an FSSAI audit, and how to safely modify this software if you ever need to add new features.

1. The Daily Floor SOPs

This is how spice moves through our facility. Rule #1: Nothing moves without a barcode.

A. RM Inwarding (Receiving Goods)

  1. Open the Inwarding tab.
  2. Log the incoming raw material, select the vendor, and enter the weight of a single bag.
  3. Enter the total number of bags and click Stage for Printing.
  4. Physical Action: Print the generated QR stickers and paste them directly onto the physical gunny bags immediately.

B. Pre-Process (Cleaning, Roasting, Base Blends)

  1. Open the Pre-Process tab.
  2. Select the target process (e.g., Blending Garam Masala).
  3. Scan all the raw material barcodes you are pouring into the machine.
  4. Enter the final total yield weight and click Generate WIP Tags.
  5. Physical Action: Paste the new WIP (Work-In-Progress) tags on the intermediate storage drums.

C. Final Batch Execution

  1. Open the Scanner tab.
  2. Select your name and the final recipe.
  3. Click Resume and scan every WIP drum and Raw Material bag going into the final blender.
  4. Click FINISH to securely lock the FSSAI record.

D. Yield & Packet Reconciliation

  1. Open the Yield tab.
  2. Enter the Batch Code and the Target Weight per run (in grams).
  3. For each run, input the actual Gross Weight from the floor scale and the number of Silver Packets used.
  4. The system will auto-calculate your Net Yield and Loss %. Click Save to Dashboard.
  5. Physical Action: Click Print Batch Annexure and have QA sign the physical paper.

2. FSSAI Audits & Disaster Recovery

Handling FSSAI Audits: If an auditor asks for traceability records for a specific batch of spices, open the Dashboard. Search for the batch code, and click Export FSSAI Report. The system will generate a secure, 1-page PDF showing exactly which vendor supplied the raw materials used in that specific batch.

FAILSAFE: What happens if the server crashes?
Every single time a button is clicked or a barcode is scanned, this app silently broadcasts the data to a Google Sheet named "Kilrr Master Traceability Vault". If this web app goes completely offline, open that Google Sheet. Zero data is lost. Use the Google Sheet as your official FSSAI ledger until the server comes back online.

3. How the Tech Works (The Architecture)

The factory software is entirely cloud-based. Here is where everything lives:

  • GitHub (The Filing Cabinet): This holds the actual text files of the code (server.js, index.html).
  • Render.com (The Engine): This is the web server. It connects to GitHub, reads the code, and hosts the app on the internet.
  • Neon.tech (The Memory): This is the PostgreSQL database. It permanently saves every scanned barcode and batch record.

The Master Password: Currently set to 1234. You need this PIN to edit Master Data, delete batches, or delete yield records. (It can be changed inside the server.js file).

4. The Zero-Knowledge Coding Guide

If you want to add a new feature or fix a bug in this software, you do not need to know how to code. You can use an AI (like ChatGPT, Gemini, or Claude).

  1. Log into GitHub and open the code file you want to change. Copy all the text inside it.
  2. Open your AI tool and paste the "System Context Prompt" below.
  3. Paste your code, and tell the AI what you want to do (e.g., "Please make the yield save button blue.")
  4. Copy the code the AI gives you, go back to GitHub, click the Pencil Icon (Edit), delete the old code, and paste the new code.
  5. Click Commit Changes. Render.com will see the change and automatically reboot the factory server in 60 seconds.
